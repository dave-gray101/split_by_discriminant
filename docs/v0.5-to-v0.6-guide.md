# v0.5 to v0.6 Migration Guide

## Overview

v0.6 is a **breaking release** that introduces a more idiomatic and comprehensive API for the `split_by_discriminant` library. The core functionality remains unchanged — everything is about making reference access more intuitive and complete.

## Method Renamings: `extract_*` → Idiomatic Rust Patterns

### Primary Change: New Naming Scheme

The v0.5 `extract_*` family has been replaced with **idiomatic Rust method names** that match patterns from `std::option::Option` and `std::result::Result`:

| v0.5 Method | v0.6 Method | Semantics | Returns |
|-------------|-------------|-----------|---------|
| `extract_simple(id)` | `as_mut_simple(id)` | Non-removing mutable ref access | `Option<Vec<&mut U>>` |
| `extract<U>(id)` | `as_mut<U>(id)` | Non-removing mutable ref access | `Option<Vec<&mut U>>` |
| `extract_gat<S>(id)` | `as_mut_with<S>(id)` | Non-removing mutable ref access | `Option<Vec<...>>` |
| `extract_with(id, f)` | `map_as_mut(id, f)` | Non-removing mutable ref via closure | `Option<Vec<&mut U>>` |

### Why This Change?

Rust's standard library conventions use:
- **`as_mut()`** for fallible `&mut` reference access (e.g., `Option::as_mut()`, `Result::as_mut()`)
- **`map()`** or **`map_as_mut()`** for closure-based transformations

The v0.6 naming aligns `split_by_discriminant` with these established patterns, making the API more discoverable and predictable for Rust developers.

## Migration Examples

### Simple Usage

**v0.5:**
```rust
let mut ex = SplitWithExtractor::new(split, MyExtractor);
let ints = ex.extract_simple(a_disc).unwrap();
```

**v0.6:**
```rust
let mut ex = SplitWithExtractor::new(split, MyExtractor);
let ints = ex.as_mut_simple(a_disc).unwrap();
                ^^^^^^^^^^^^^^
```

### Parametrized Extraction

**v0.5:**
```rust
let strings: Vec<&mut String> = ex.extract::<String>(b_disc).unwrap();
```

**v0.6:**
```rust
let strings: Vec<&mut String> = ex.as_mut::<String>(b_disc).unwrap();
                                    ^^^^^^^^
```

### Generic Selector Extraction

**v0.5:**
```rust
let pairs = ex.extract_gat::<SelectPair>(id).unwrap();
```

**v0.6:**
```rust
let pairs = ex.as_mut_with::<SelectPair>(id).unwrap();
                ^^^^^^^^^^^^
```

### Closure-Based Extraction

**v0.5:**
```rust
let ints = ex.extract_with(a_disc, |e| {
    if let MyEnum::A(v) = e { Some(v) } else { None }
}).unwrap();
```

**v0.6:**
```rust
let ints = ex.map_as_mut(a_disc, |e| {
    if let MyEnum::A(v) = e { Some(v) } else { None }
}).unwrap();
    ^^^^^^^^^^^
```

## New Methods Added in v0.6

Beyond the method renames, v0.6 adds a substantial set of new functionality:

- **`as_ref_*` variants** — Immutable reference access without a `&mut self` borrow:
  `as_ref_simple`, `as_ref<U>`, `as_ref_with<S>`, `map_as_ref`, and their `*_multiple_*`
  batch counterparts. These require `SimpleReadFrom<T>` / `VariantReadFrom<T, U>` /
  `ReadFrom<T, S>` impls. `#[derive(ExtractFrom)]` generates all three automatically
  alongside the mutable impls.
- **Batch reference methods** — `as_mut_multiple_simple`, `as_mut_multiple<U>`,
  `as_mut_multiple_with<S>`, `map_as_mut_multiple`, and the corresponding `as_ref_multiple_*`
  counterparts.
- **`GroupMut<'_, G>`** — A newtype wrapper returned by `get_mut` and yielded by
  `for_each_group_mut`. Exposes iteration, sorting, and positional read-only access while
  intentionally omitting `IndexMut` to prevent accidentally writing the wrong variant back
  into a slot.
- **`for_each_group_mut(ids, f)`** — Call a closure `f(discriminant, GroupMut)` for each
  present discriminant in `ids`. Replaces the former `get_multiple_mut`, which has been
  removed.
- **`extract_with(id, f)` / `extract_multiple_with(ids, f)`** — Borrow a group mutably
  and return **owned** `U` values via an inline closure, without removing the group.
  **Do not confuse with the v0.5 `extract_with`** that was renamed to `map_as_mut`:
  these new methods return owned values rather than `&mut U` references.

## `DiscriminantMap` Direct Usage

If you use `DiscriminantMap` directly (not through `SplitWithExtractor`), the same renamings apply:

**v0.5:**
```rust
let map = split_by_discriminant(&mut data, &[a_disc, b_disc]);
let ints = map.extract_with(a_disc, |e| /* ... */).unwrap();
```

**v0.6:**
```rust
let map = split_by_discriminant(&mut data, &[a_disc, b_disc]);
let ints = map.map_as_mut(a_disc, |e| /* ... */).unwrap();
                   ^^^^^^^^^^^
```

## Complete Renaming Reference

### `SplitWithExtractor` Methods

All these apply to `SplitWithExtractor<T, G, O, E>`:

```
extract_simple()     → as_mut_simple()
extract<U>()         → as_mut<U>()
extract_gat<S>()     → as_mut_with<S>()
extract_with()       → map_as_mut()
```

### `DiscriminantMap` Methods

All these apply to `DiscriminantMap<T, G, O>`:

```
extract_with()       → map_as_mut()
```

> **Note:** v0.6 also introduces a *new* method named `extract_with(id, f)` on
> `DiscriminantMap`. This is **not** the same as the v0.5 `extract_with` that was renamed
> to `map_as_mut`. The new `extract_with` returns **owned `U` values** (via a closure that
> may return any `U`) without removing the group. If you see a compile error pointing to a
> *new* `extract_with` method, check whether you intended `map_as_mut` (for `&mut U`
> references) or the new `extract_with` (for owned values).

## Backwards Compatibility

**No automatic compatibility layer is provided.** You must update call sites to use the new method names. This is intentional — v0.6 is a breaking release meant to establish more correct long-term naming.

Search-and-replace cheatsheet:
```bash
# Replace extract_simple → as_mut_simple
find . -name "*.rs" -type f -exec sed -i 's/\.extract_simple(/\.as_mut_simple(/g' {} \;

# Replace extract< → as_mut<  
find . -name "*.rs" -type f -exec sed -i 's/\.extract</\.as_mut</g' {} \;

# Replace extract_gat → as_mut_with
find . -name "*.rs" -type f -exec sed -i 's/\.extract_gat:/\.as_mut_with:/g' {} \;

# Replace extract_with → map_as_mut
find . -name "*.rs" -type f -exec sed -i 's/\.extract_with(/\.map_as_mut(/g' {} \;
```

## Extractors and Traits: No Changes

The extraction trait system remains unchanged:
- `SimpleExtractFrom<T>` — same API
- `VariantExtractFrom<T, U>` — same API
- `ExtractFrom<T, S>` — same API
- `TakeFrom<G, S>` — same API

If you implement extractors, no changes are needed. Only the **call sites** that invoke extraction methods need updates.

## Common Error Messages and Fixes

### Error: `no method named 'extract_simple'`

```
error[E0599]: no method named `extract_simple` found
```

**Fix:** Rename to `as_mut_simple`

### Error: `no method named 'extract' found`

```
error[E0599]: no method named `extract` found     
```

**Fix:** Rename to `as_mut` (add turbofish if needed: `as_mut::<U>()`)

### Error: `no method named 'extract_gat' found`

```
error[E0599]: no method named `extract_gat` found
```

**Fix:** Rename to `as_mut_with`

### Error: `no method named 'extract_with' found`

```
error[E0599]: no method named `extract_with` found
```

**Fix:** Rename to `map_as_mut`

## Testing Your Migration

After updating method names, run your full test suite:

```bash
cargo test
```

Since the renaming is purely syntactic (method signatures and behavior are identical), passing tests confirm the migration is complete.

## What Stays the Same

- **Group partitioning logic** — identical
- **Trait system** — extractors and trait impls unchanged
- **Lifetime semantics** — `TakeFrom` still preserves full lifetimes
- **Module structure** — same public API surface
- **Feature flags** — `indexmap` feature unchanged
