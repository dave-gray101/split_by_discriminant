# Migrating from v0.4 to v0.5

This guide helps you upgrade code from v0.4 to v0.5. If you're starting fresh with v0.5, the core sections below explain the current API design — you can skip the "v0.4 → v0.5 comparison" sections.

## Overview

v0.5.0 is a significant API refinement that:
- Renames core types and methods for consistency with common Rust patterns
- Introduces clearer extraction traits that reflect actual usage patterns
- Adds convenient shorthand methods for common cases

## Key Changes at a Glance

| Old (v0.4) | New (v0.5) | Notes |
|---|---|---|
| `SplitByDiscriminant<T, G, O>` | `DiscriminantMap<T, G, O>` | Main result type renamed |
| `group(id)` | `get(id)` | Read-only group access |
| *(none)* | `get_mut(id)` | **New:** mutable group access |
| `take_group(id)` | `remove(id)` | Consuming group removal |
| `take_group_mapped(id, f)` | `remove_mapped(id, f)` | Mapped removal |
| `take_group_with(id, f)` | `remove_with(id, f)` | Filter-map removal |
| `take_others()` | `remove_others()` | Unmatched items removal |
| `map_groups(f)` | `map_all(f)` | Consuming map over all groups |
| *(none)* | `map_others(f)` | **New:** transform the others vector |
| `.groups` (internal) | `.entries` (internal) | Map field name |

## Renaming Update

The simplest migration is a name-by-name find-and-replace:

**Before:**
```rust
use split_by_discriminant::{split_by_discriminant, SplitByDiscriminant};

let mut split = split_by_discriminant(&mut data, &[a_disc, b_disc]);
let group: Option<&[Item]> = split.group(a_disc);
let removed: Option<Vec<Item>> = split.take_group(b_disc);
split.take_others();
split.map_groups(|grp| grp.len()).into_parts();
```

**After:**
```rust
use split_by_discriminant::{split_by_discriminant, DiscriminantMap};

let mut split = split_by_discriminant(&mut data, &[a_disc, b_disc]);
let group: Option<&[Item]> = split.get(a_disc);
let removed: Option<Vec<Item>> = split.remove(b_disc);
split.remove_others();
split.map_all(|grp| grp.len()).into_parts();
```

## Extractor Trait Changes

The key change in extraction is the introduction of `VariantExtractFrom<T, U>` as the primary trait for multi-variant extractors, which eliminates the need for selector ZSTs in the common case.

**For v0.4 users:** The v0.4 pattern of `ExtractFrom<T, Selector>` with selector ZSTs is now reserved for edge cases (multi-field outputs, duplicate field types). The new `VariantExtractFrom<T, U>` trait lets you implement multiple times with binding-inferred `U`, matching the ergonomics you had in v0.4.

**For detailed trait selection and implementation guidance,** see [four-crate-pattern-guide.md](four-crate-pattern-guide.md) — it covers all traits, decision trees, and best practices.

## Example: Upgrading from v0.4

If you're upgrading a multi-variant extractor from v0.4, the key change is using `VariantExtractFrom` instead of `ExtractFrom` with selector ZSTs.

**Before (v0.4):**
```rust
use split_by_discriminant::{split_by_discriminant, ExtractFrom, SplitWithExtractor};
use std::mem::discriminant;

#[derive(Debug)]
enum E { A(i32), B(String), C }

struct MyExtractor;

// v0.4: selector ZSTs were needed
struct SelectA;
struct SelectB;

impl ExtractFrom<E, SelectA> for MyExtractor {
    type Output = i32;
    fn extract_from<'a>(&self, t: &'a mut E) -> Option<&'a mut i32> {
        if let E::A(v) = t { Some(v) } else { None }
    }
}

impl ExtractFrom<E, SelectB> for MyExtractor {
    type Output = String;
    fn extract_from<'a>(&self, t: &'a mut E) -> Option<&'a mut String> {
        if let E::B(s) = t { Some(s) } else { None }
    }
}

let mut data = vec![E::A(1), E::B("hi".into()), E::A(2), E::C];
let a_disc = discriminant(&E::A(0));
let b_disc = discriminant(&E::B(String::new()));

let mut split = split_by_discriminant(&mut data, &[a_disc, b_disc]);
let mut ex = SplitWithExtractor::new(split, MyExtractor);

// v0.4: turbofish required for selectors
let ints: Vec<&mut i32>    = ex.extract_gat::<SelectA>(a_disc).unwrap();
let strs: Vec<&mut String> = ex.extract_gat::<SelectB>(b_disc).unwrap();

// Method names also changed:
let others = ex.remove_others();  // was: take_others()
```

**After (v0.5):**
```rust
use split_by_discriminant::{split_by_discriminant, VariantExtractFrom, SplitWithExtractor};
use std::mem::discriminant;

#[derive(Debug)]
enum E { A(i32), B(String), C }

struct MyExtractor;

// No selector ZSTs needed — VariantExtractFrom with type parameter U
impl VariantExtractFrom<E, i32> for MyExtractor {
    fn extract_from<'a>(&self, t: &'a mut E) -> Option<&'a mut i32> {
        if let E::A(v) = t { Some(v) } else { None }
    }
}

impl VariantExtractFrom<E, String> for MyExtractor {
    fn extract_from<'a>(&self, t: &'a mut E) -> Option<&'a mut String> {
        if let E::B(s) = t { Some(s) } else { None }
    }
}

let mut data = vec![E::A(1), E::B("hi".into()), E::A(2), E::C];
let a_disc = discriminant(&E::A(0));
let b_disc = discriminant(&E::B(String::new()));

let mut split = split_by_discriminant(&mut data, &[a_disc, b_disc]);
let mut ex = SplitWithExtractor::new(split, MyExtractor);

// U inferred from binding — no selectors needed!
let ints: Vec<&mut i32>    = ex.extract(a_disc).unwrap();
let strs: Vec<&mut String> = ex.extract(b_disc).unwrap();

let others = ex.remove_others();
```

## Notes

- `ExtractFrom<T, Selector>` with `type Output<'a>` (a GAT) is needed only for multi-field tuple/struct outputs, lifetime-carrying fields, or duplicate field types across variants. Most extractors use `VariantExtractFrom` or `SimpleExtractFrom` instead.
- All extraction traits (`SimpleExtractFrom`, `VariantExtractFrom`, `ExtractFrom`, `TakeFrom`) are re-exported from the crate root for easy import.
- For the factory/four-crate pattern, see [four-crate-pattern-guide.md](four-crate-pattern-guide.md) for detailed guidance and decision trees.
- The binding-annotation style (where `U` is inferred from the expected type) eliminates the need for turbofish in the common case of multiple variants with distinct field types.
